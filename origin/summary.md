## 2. ONY-YOW とは何か

### 2.1 定義 (p106, p108)

```
ONY（未来向き・計画）        YOW（過去向き・検証）
  O: 起きていること            Y: やったこと
  N: 望んでいること            O: 起きたこと
  Y: やってみること            W: 分かったこと
```

**やり方は、この6つをそのまま問いかけるだけ** (p110-113)。

- ONY の3問に答える → **計画**になる
- YOW の3問に答える → **実行結果の検証**になる

Y が両方に現れる（やってみること／やったこと）のが2つの三つ組の接続点。

> **補足**: ONY/YOW の未来・過去という対比は既定の姿にすぎない。
> YOW は時制を移すことで**事前・最中・事後**の3通りに使え、事前の YOW は仮説立案（未来向き）になる (p122-125、§2.4)。

### 2.2 4カテゴリの定義 (p134-138)

仕事で使う無数の言葉は、おおよそ4つの箱に収まる。

| 記号 | カテゴリ | 定義 | 属する言葉 |
|---|---|---|---|
| **O** | 起きていること | **判断に影響する観察された事実** | 状況、状態、現状、場面、事態、様子、環境、文脈、背景、兆候 |
| **N** | 望んでいること | **実現したい状態** | 目的、ねらい、趣旨、意図、意義、ビジョン、方針、目標、動機、関心 |
| **Y** | やってみること | **自分たちが実行可能な行動** | 行動、活動、実行、実践、施策、打ち手、対応、決定、判断、選択 |
| **W** | 分かったこと | **原因が結果を引き起こすメカニズムの説明** | 理論、仮説、仮定、推測、推論、予測、見立て、帰納、演繹、アブダクション、洞察 |

各定義の効きどころ:
- O は「事実」だが無制限ではなく「**判断に影響する**」ものに限られる
- N は行動ではなく「**状態**」として書く
- Y は「**自分たちが実行可能**」— 他人任せの願望を排除する
- W は知識ではなく「**因果のメカニズム**」の説明を要求する

### 2.3 ONY-YOW は「文法」である (p139)

> ONYとYOWは各概念カテゴリの組合せパターン
> 概念と概念を結びつける「**スキルの文法規則**」(英語のSVOCと同じ)

これが本デッキの理論的中核。ONY-YOW はフレームワークではなく**文法**だと位置づけられている。
個々の専門用語（語彙）を覚えるのではなく、語を4つの品詞に分類し、その並べ方の規則を覚える。
有限の規則で無限の文が作れるように、有限の要素で多様な場面に対応する、という主張。

### 2.4 全体表 (p126-129)

| | 事前 | 最中 | 事後 |
|---|---|---|---|
| **O** (観察した) | 起きていること | — | — |
| **N** (起きている状況で) | 望んでいること | — | — |
| **Y** (望みに向けて) | やってみること | やっていること | やったこと |
| **O** (やってみる結果) | 起こりそうなこと | 起きていること | 起きたこと |
| **W** (行動と結果から) | 分かりそうなこと | 分かりつつあること | 分かったこと |

- O と N は「事前」列にしか値がない。**状況認識と望みは行動前に一度定める**もの
- 2つ目の O が、説明テンプレートに出てくる `O2`（予測される結果）
- 時制を変えるだけで、同じ3要素が **仮説立案 / 過程の説明 / 仮説の検証** に変わる (p122-125)

## 3. なぜこの形なのか — 設計原理 (p86-102)

言語能力を短期間で伸ばすために、著者は4つの方針に絞った。

| 方針 | 比喩 | 何を上げるか |
|---|---|---|
| 1. **使う言葉に時間をかける** | ハイスピードカメラ (p88-89) | 時間解像度 |
| 2. **言葉の構造を判断しやすくする** | 顕微鏡・望遠鏡 (p90-93) | 空間解像度（要素間の関係） |
| 3. **全体の質を左右する少数の要素に集中する** | 4カテゴリへの圧縮 (p94-99) | 学習コスト削減 |
| 4. **言葉を練習する頻度を高める** | 日々の実務が練習になる (p100-102) | 練習回数 |

> 練習と本番に分けるのではなく、**普段の日々のどのような仕事でも練習でき、学習と同時に成果に繋がる**方法なら身につけやすくなります。(p101)

ONY-YOW が「6つの問い」だけで済むこと（=実行時間が短いこと）が、方針4を可能にしている。

## 4. タイトルの答え — なぜ年3000回か (p157-160)

### プラクティスエフェクト (p158)

> スキルやプラクティスは使うほど上手になり、使わないほど下手になります。
> この効果を左右する2つの性質が **機会頻度** と **実行時間** です。
>
> 1年に一回しかやらないものはうまくなりません。確定申告、年末調整は得意にはなりづらいです。**いつまでも初心者のままです。**

※ SF作家デイヴィッド・ブリン『プラクティス・エフェクト』が元ネタ。

### 計算 (p160)

```
1日の仕事を30分のタスクで区切る → 1日8時間で16回
16回/日 × 年間営業日200日 = 3200回/年
```

- 朝に **ONY** で1日の計画を立て、夕方に **YOW** で結果を検証する
- さらに定例MTGの最初の1分、チャット送信前の30秒、AIへの依頼など**1-2分の場面**でも実行でき、練習量を上積みできる

**要点は3000という数字ではなく、練習の単位をタスク1件まで小さくしたこと。**

## 5. 6つのスキルは4要素の操作である (p142-146)

タイトルにある6つの活動が、ONYW の組み合わせに還元される。**このデッキで最も実務的な一枚。**

| スキル | 要素の結びつけの操作 | 使う要素 |
|---|---|---|
| **観察** | N望んでいることに照らして O事実を選び認識する | O / N |
| **仮説立案** | Y行動が O結果を引き起こす W説明を組み立てる | Y / O / W |
| **実行** | N目的とW理解を把握しながら O現状と比べてY行動する | O / N / Y / W |
| **仮説の検証** | Yやったことと O2実際に起きたことを突き合わせ W分かったことを更新する | Y / O2 / W |
| **計画** | O現状とN望みを明らかにし、そのギャップを埋めるY行動を選ぶ | O / N / Y |
| **提案** | 相手のO現状認識とN望みに合わせて自分のONY提案を組み立て、**要素ごとに**同意を得る | 自分と相手の ONY（各2組） |

読みどころ:
- **「観察」に N が入っている** — 目的なしの観察は観察ではない、という立場
- **「提案」だけが要素を2倍持つ** — 提案が最も難度の高いスキルである理由の説明になっている

### 提案は同意を3回に分割する (p147-149)

| | 提案側 | 相手 |
|---|---|---|
| O | 「○○という状況が起きています」 | 「たしかに それが起きてる」← **Oに同意** |
| N | 「○○が望まれていると思います」 | 「たしかに それを望んでる」← **Nに同意** |
| Y | 「○○という方法で近づけられると考えています」 | 「それで進めよう」← **Yに同意** |

まとめて「どうですか」と聞かない。**どこで合意が崩れたかを特定できる**のが利点。

## 6. 診断ツール — 要素を引き算すると何になるか (p150-152)

**このデッキで最も実用的な表。** 日常的な失敗に、欠落した要素として名前がつく。

| 引き算 | 結果 |
|---|---|
| 観察 ON から、目的 N を除く | **見ただけ** |
| 仮説立案 YOW から、理解 W を除く | **ただの予測** |
| 実行 Y から、理解 W を除く | **作業をこなすだけ** |
| 計画 ONY から、状況 O を除く | **机上の空論** |
| 提案 ONY から、相手の O と N を除く | **押し売り** |
| 提案 ONY から、自分の計画 ONY を除く | **御用聞き** |

> ミスをしたとしても単に反省するのではなく、要素を足したり、外したりして、「**スキルの性質を変える**」ということを試します。(p152)

実践のヒント:
- 机上っぽくなったら → **O 起きていることを確認する**
- 方向性が見えないなら → **N 望ましいことを見出す**
- ごちゃごちゃしたら → **減らしてみる**

改善策が「反省」ではなく「**要素の足し引き**」という機械的操作になっている点が、
p38 で掲げた「原理に透明な方法」の具体化にあたる。

## 7. 使い方

### 7.1 人に説明する (p116-120)

```
O : 起きている○○という状況で、
N : 望んでいる○○という目的のために、
Y : やってみる○○という行動をします。
O2: すると起きそうな○○という結果が期待できます。
W : 分かっている○○が働くためです。
```

実演例 (p119):
> O : 自社で生成AIの利用者が伸び悩む状況です。
> N : AIを活用できる組織に向けて
> Y : 生成AI関連の勉強会でリサーチします!
> O2: 現在のベストプラクティスの把握が期待できます!
> W : 勉強会では失敗と成功事例が共有されるからです!
> N : AIが活用できる組織に近づけられます!
>
> → 上司「**把握!**」

Before は「話題のイベントがあるみたいなのでいってみたいっす!」→ 上司「(なんでいくの?)」。
同じ要求が、5点セットになった瞬間に**承認可能な提案**へ変わる。

### 7.2 会議を始める (p161)

```
現在、O起きている○○という状況で、
N望んでいる○○という目的に向けて、
今回の定例MTGではY ○○をやってみます。
```

> 定期的に行うとしても、**状況も目的も毎回異なるはず**です。

### 7.3 生成AIとやりとりする (p121, p166-168)

**入力側** — 「AIにどう伝えたらいいのか分からない」
→ **やってもらうことを ONY で整理してから伝える**

**出力側** — 「AIからの大量の情報をどう受け止めたらいいのか分からない」
→ **ONY に絞って整理する**（篩として使う）

ONY-YOW は上司への説明の型であると同時に、
そのまま **AI に渡すコンテキストの単位**になる (p121)。ここで冒頭の「2つの悩みを一度に解決」が回収される。

### 7.4 専門手法を読み解く (p153-156)

> プラクティスもフレームワークも、ONYWで構造を解きほぐし、理解することができます。
>
> O: その方法は現状をどのように説明するのか?
> N: その方法はどのような目的があるのか?
> Y: どのような手順を行うのか? どう介入するのか?
> W: その方法は、どのようなメカニズムによって現状から目的に近づけるのか?

企業決算も「**ONY + 専門ツール（財務三表）**」という構造として読める (p154-155)。
これが p19-38 で提起した「原理に鈍感」への解毒剤にあたる。

### 7.5 自己適用 (p163-165)

このプレゼン自体が ONY で構成されていることを開示している。

| 章 | ONY | ページ数 |
|---|---|---|
| 技術と原理に鈍感／生成AIの性能向上／やりとりは言語が中心 | **O** | 100ページ |
| 言葉とその構造と頻度から練習する | **N** | 20ページ |
| 仕事の基本はONY-YOW／アドバンスドONY-YOW | **Y** | 150ページ |

## 8. アドバンスド ONY-YOW (p172-244)

基本編が「要素をどう並べるか（構造）」なら、アドバンス編は「**各セルの中身の質を上げる**」。
各節の冒頭で、同じ全体表に別の矢印を引いて扱う関係を明示する構成になっている。

### 8.1 言葉の明確さ、事実の確からしさ (p174-195)

**手順は明瞭さが先、事実性が後** (p180)。不明瞭な文では事実かどうかも確かめられないため。

**明瞭さ** (p186-188)
> 明瞭さとは**文が適切な場面で一つの意味になっていること**。
> 明瞭であることと事実であることは別。はっきり書かれた誤情報もあれば、事実でも曖昧な文もある。
> **完全文で表現しましょう**（文章に必要な要素が揃っていること）。

- クイズ: 「Two Zero Two Six は数字にするといくつ? → 2026? 0066? 0026? 2066?」(p183-185)
- 例: 「みんな計画!!計画!計画だよ!!!」→ 「**みんなで今週の計画を見直そう!**」

**事実の確からしさ** (p189-192)
> 測った / 撮った / 自分で見た / 人から聞いた / 推測 / 妄想…
> **この順で確からしさは弱くなります。**

主張だけでなく「どうやって知ったか」を添える運用。「**出所はここ!**」

**この節の結論** (p193-195)
> 「**分かればいい**」は早いが **分かる人までにしか伝わらない**
>
> 自分たちの仕事、プロダクトが自分たちの手から離れて社会で活躍するようにしたいなら、
> より多くの人に誤解なく伝わるように日頃から言葉を表現する必要がある

### 8.2 因果関係 — 原因/結果/交絡 (p196-212)

表の **Y → O（下向き）**の連結を扱う。

- 原因とは結果を引き起こす現象。結果とは原因が引き起こす現象 (p200-201)
- **行動Yの後に状況Oが起きても「YがOを引き起こした」とは言いきれない**。別の原因や交絡がありうる (p202)

**クイズ** (p203-208)
| 誤 | 正 |
|---|---|
| 熱がある → 風邪をひいた | **風邪をひいた → 熱が出た** |
| 窓から煙 → 火事が起きている | **火事が起きている → 窓から煙** |

> **煙から火事を推測することは適切な推論の順序です。誤りは推論の順序をそのまま因果として認識したことです。**

**交絡** (p209-211)
> 2つの事象に共通の原因があるために、2つの事象に因果があるように見え、原因を取り違えること。
> ✗ アイスの売上が増えると熱中症が増える
> ○ **気温がアイスの売上と熱中症を引き起こす**（両者に因果関係はない）

**結論** (p212)
> 私たちが**見た聞いた考えたという順序**と**実際の因果関係**は関係がない。
> **推論過程と因果関係の混同に注意。**

### 8.3 必要条件 / 十分条件 / 最小十分条件 (p213-233)

表の **Y → N（上向き）**の連結を扱う。「ONYとYOWが実行可能で経済価値を持つかを評価する」

導入例 — 電車に間に合うように駅へ向かう (p217):

| 条件 | 内容 |
|---|---|
| 必要条件 | 電車に乗るために駅に向かう必要がある |
| 十分条件 | 駅に1時間前に到着すれば乗れる。しかし1時間前は時間をもてあます |
| 最小十分条件 | 出発時刻の10分前に到着**さえすれば**乗れる |

| 条件 | 言い回し | 性質 | 判定の問い |
|---|---|---|---|
| **必要条件** | 「○○**には**必要」 | 欠かせないが、それだけでは足りない | 欠けると目的が実現できなくなるか (p221) |
| **十分条件** | 「○○**があれば**成立」 | 達成できるが**過剰を含む** | ○○があれば確実に実現できるか (p227) |
| **最小十分条件** | 「○○**さえあれば**成立」 | 1つも外せない。過不足なし | ちょうど○○さえあれば実現できるか (p231) |

**十分条件からの絞り込み** (p228, p231)
> 確認する問いかけは「**ひとつ外すなら?**」
> ・外して結果が変わらなければ不要 ・外して結果がまずくなれば必要
>
> 十分条件からひとつずつ外して**結果が出なくなる前で止める**
>
> オペレーション設計 = **最小十分条件 + 不確実性に対応するためのバッファ**

**過剰さの名指し** (p228)
> 過剰品質、過剰な多機能／**調査や分析しすぎ、計画を詳細にしすぎ、確認しすぎ**
>
> 許容可能な失敗のために何倍ものコストをかけるのは収益性から見ると失敗です。

> **初心者は過剰か過小になってしまいます。プロフェッショナルはちょうどよく実現します。** (p231)

**実践法** (p232-233)
> おすすめの方法は **ホワイトボードに書く**
> 手書きは、限られた時間と書く労力によって、より少数の重要な情報へと絞り込むことになる。

### 8.4 因果推論 — 前向き / 後ろ向き (p234-242)

| | 別名 | 構造 | 例 |
|---|---|---|---|
| **前向き推論** | 予測推論 | 原因 → 結果 → 結果 | 「○○するとどうなる?」経験から推測しやすく、普段行っている考え方 |
| **後ろ向き推論** | 診断推論 | 結果 ← 原因 ← 原因 | 「○○という結果を引き起こした原因はなに?」バグ・故障の特定、医師の診断 |

> 後ろ向き推論は、**結果を引き起こすと考えられる複数の原因を推測し、そこからもっともらしい原因を選択する**点で難易度が高い。いつもの思考の枠を越えて、より広い集合を考えることが必要だから。
> **なぜなぜ5回が難しいのは、これを5回繰り返すからです。** (p240)

さらに難しい点は**粒度**の選択 (p241):
> ・風邪ウイルスにかかるとどうなる? → 熱が出る
> ・風邪ウイルスにかかるとどうなる? → ウイルスが増殖する

**ONY での運用（2×2）** (p242) — アドバンス編で最も実用度が高い:

| 場面 | 向き | 記法 | 問い |
|---|---|---|---|
| 行動と結果の予測 | 前向きで予測 | `Y→O` | やったら起きそうなことは何? |
| 行動と結果の検証 | 後ろ向きで検証 | `O←Y` | ○○が起きたのは○○をしたから? |
| 目的への手段の選択 | 後ろ向きで選択 | `N←Y` | 目的のために、様々な方法Yがある中でなにをするべき? |
| 手段の妥当性の検証 | 前向きで検証 | `Y→N` | やると目的を実現できるのか |

> 「三ヶ月後プロジェクトは大失敗してしまった。何が原因だったのか」
> この**プレモーテムも後ろ向き推論 `O←Y`**

### 8.5 企業の全体構造を把握する (p243-244)

ONY-YOW が個人のタスクから**組織階層**へスケールする。接続規則はただ一つ。

> **上位の行動Yを実現するのに必要な状態が、下の目的Nになります。**

```
経営層   ONY ⇄ YOW   年次〜四半期
            ↓  (上位のY = 下位のN)
中間層   ONY ⇄ YOW   月次〜週次
            ↓
現場     ONY ⇄ YOW   日次
```

これによって、p160 の「1日16回」という個人の練習が、企業全体の計画構造の一部として位置づけられる。

## 10. 論として押さえておくべき点

**強いところ**

- **手法の実体が6つの問いしかない。** 覚えるコストが低く、実行時間が短い。だから高頻度で回せる。手法の設計と主張（練習しやすいと上達しやすい）が一致している。
- **引き算の診断表 (p150)** が優れている。「押し売り」「御用聞き」「机上の空論」という日常語が、どの要素の欠落かとして機械的に診断でき、改善策も「要素を足す／外す」という操作になる。
- **自己適用している (p163-165)。** 手法の説明資料が、その手法自身の構造で作られていることを開示している。「原理に透明」という要求を自分で満たしてみせている。
- **自陣営を刺している (p30)。** スクラムを「原理に鈍感なまま機能してしまう仕組み」の実例として挙げる。Scrum Fest での発表であることを踏まえると意図的。

**検討の余地があるところ**

- **年3200回は「機会の数」であって「練習の質」ではない。** p160 の計算は 30分タスク × 8時間 × 200日 という上限値で、すべてのタスクに ONY-YOW を適用した場合の理論値。デッキ自身も「機会があります」と書いており実測値ではない。
- **「仕事の概念はおおよそONYWのどれか」(p133) は、PDF に含まれる範囲では論証されていない。** 4分類の網羅性は宣言されるが、なぜ4つで足りるかは示されない。制約や資源、リスク、価値といった語がどこに入るかは読者に委ねられる。
- **W（分かったこと）が最も難しく、最も薄い。** W は「原因が結果を引き起こすメカニズムの説明」と定義され、アドバンス編の因果関係・因果推論がここを支えるが、日々3000回のループの中で W を毎回まともに書けるかは別の問題。
- **PDF は元デッキの全部ではない。** 印字番号の飛び（149-155、225-228、274、276-279 など）から、PDF に出ていないスライドの存在が読み取れる。当日の口頭説明や具体例、上記の論証がそこにあった可能性は排除できない。上の批判はいずれも **PDF に含まれる251ページの範囲での評価**。
