# /yow — 夕方: 今朝の Y から結果と教訓を聞き出し、PR に積む

共通規約は [CLAUDE.md](../../../CLAUDE.md)、型の正本は [ontology.yaml](../../../ontology.yaml)。

## 手順

1. **当日のブランチへ** — `date +%Y-%m-%d` で日付を取り、`day/<YYYY-MM-DD>` に switch
   （無ければ「今朝の /ony がまだです。先に記録しますか？」と聞く。過去日の未検証を
   検証するなら、そのブランチが残っていればそこへ、マージ済みなら main から
   `day/<今日>-yow` を切る）。
2. **今朝の Y 一覧を出す** — `uv run --with pyyaml --no-project python3 tools/oylint.py --pending`
   から当日分（無ければ古い未検証も）を、**ID / title / Y / O2** の表で見せる。
   上から順に1件ずつ聞いていく（ユーザーが選び直してもよい）。
3. **各ループについて聞く** — **1問1回答**（一度に1つだけ問い、答えを受けてから次へ）。
   元の ONY カードの **O2 を逐語で**見せてから:
   - 「**結果どうでしたか？**」→ **O**（起きたこと・観測された事実）。
     感想が返ったら**1回だけ**突き返す: 「それは感想です。**何が観測されました**か」
   - O2 との一致・不一致は**ユーザー自身に言わせる**（こちらが判定しない）。
     O2 が空なら「予測なしの検証です（突き合わせはできません）」と1行伝えて進む
   - 「そこから**何が分かりましたか？**」→ **W**（教訓。自由記述 — 規律を課さない）。
     ただし O2 と食い違ったのに W が事前の見立てのままなら
     「食い違いは W に反映しなくていいですか」と**1回だけ**聞く
   - Y は実際にやったことが朝の記述と違えばその旨を書く
   - **ONY カードは開いて読むだけ。書き換えない**（凍結はファイル分離が担保）
4. **カード作成** — `templates/yow.md` から `raw/yow/<同じID>.md` を件数分作る
   （frontmatter の `ony:` は自分の ID と同じ — same-id 規則）。
5. **lint とデッキ再生成** — oylint（error は直す）→
   `uv run --with pyyaml --no-project python3 tools/gen_deck.py`
   （週デッキのループスライド右列と W カタログに反映される）。
6. **カードごとに単独コミットして PR に積む**:
   ```bash
   git add raw/yow/<ID>.md && git commit -m "yow: <ID>"
   # 最後に
   git add wiki/ && git commit -m "wiki: <日付> 夕の再生成" && git push
   ```
7. **ready 化とレビュー（自動）** — PR 本文を夕の状態（下段が埋まった表）で作り直し、
   ドラフトを外し、そのままレビューを実行する（**push 済みであること** — スライドの URL は
   その SHA で固定される）:
   ```bash
   uv run --with pyyaml --no-project python3 tools/gen_pr_body.py > /tmp/pr-body.md
   gh pr edit <番号> --body-file /tmp/pr-body.md
   gh pr ready <番号>
   ```
   続けて **[/onyw-review の手順](../onyw-review/SKILL.md) をそのまま実行**し、
   3観点（バイアス / 因果の弱さ / 別の選択肢）のコメントを PR に投稿する。
8. **締め** — 完成した1日（朝の O2 と夕の O が並ぶスライド）とレビューコメントの URL を見せ、
   「マージで日の確定です」と1行添える（**マージだけは本人**）。

## してはいけないこと

- **ONY カードの編集**（読むだけ。O2 の言い換え・要約もしない）
- O2 と O の一致判定の代行
- W の質への駄目出し・falsifier の要求
- マージの代行（日の確定は本人）
