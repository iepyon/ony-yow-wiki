# /ony — ONY を1行記録する

共通規約は [CLAUDE.md](../../../CLAUDE.md)（journal 行形式・6活動・引き算診断表・ISO週・パース規則）。
ここにはこのスキル固有の手順だけを書く。

## 手順

1. **今週の journal を特定する** — 現在時刻と週は暗算せず取る:
   `date +%Y-%m-%dT%H:%M`（行の日時）、`date +%G-W%V`（ISO 週）。
   ファイルは `journal/eiji-<年>-w<週>.md`（**小文字**）。無ければ CLAUDE.md の形式でヘッダから作る。
   **新しい週の最初の実行なら、前週デッキ `wiki/eiji-<前週>.md` の `status: draft` を `stable` に上げて
   main にコミットする**（flip の担い手はこのスキル）。
2. **聞く** — ユーザーの発話から O / N / Y / O2 を埋める。足りない要素だけを1つずつ短く聞く。
   長い対話にしない（目標: 全体で1〜2分。原典 p160）。
   - O: 判断に影響する観察された事実（summary.md §2.2）
   - N: 実現したい**状態**（行動ではなく）
   - Y: **自分たちが実行可能**な行動
   - O2: Y の結果として起きそうなこと。**任意だが、無いと後知恵の検査が効かないと1行だけ伝える**
   - W（分かりそうなこと）: 任意。聞かない（言われたら書く）
   - **活動が「提案」なら `相手O:` `相手N:` も聞く**（原典 §5: 提案だけが要素を2倍持つ）
3. **6活動を1語選ばせる** — `観察 / 仮説立案 / 実行 / 計画 / 提案`（検証は `/yow`）。
   実行は「途中経過の記録」として受ける。推定して提案してよいが、**決めるのはユーザー**。
4. **引き算診断** — CLAUDE.md の表を `(活動, 欠落要素)` で引き、該当したら診断名を1行返す
   （例: 計画で O が空 → 「**机上の空論**（p150）。このまま記録もできます」。
   提案で 相手O/相手N が空 → 「**押し売り**」。実行で W が空 → 「**作業をこなすだけ**」）。
   **記録は止めない**。診断は分類であって禁止ではない（p152）。
5. **追記** — 週内連番 `#NN`（ゼロ詰め2桁）を既存行の最大+1で採番し、journal の末尾に1行 Edit で足す:
   ```
   - <YYYY-MM-DDTHH:MM> #<NN> ony <活動> | O:… / N:… / Y:… / O2:…
   ```
   **本文中の半角 ` / ` は全角「／」に置換してから書く**（区切りと衝突するため）。**過去行に触らない。**
6. **コミット** — 追記したら**すぐ main にコミットする**:
   ```bash
   git add journal/ && git commit -m "journal: #<NN> ony <活動の一語>"
   ```
   yow と**別コミット**にすることが「O2 を結果より先に書いた」ことの唯一の証明になる
   （CLAUDE.md「ony 行と yow 行は別コミットにする」）。push は日次でまとめてよい。
7. **確認** — 追記した行をそのまま見せて終わる。

## してはいけないこと

- 過去行の編集・並べ替え・整形
- 6活動の自動確定（提案まで。選ぶのは人）
- W の内容への駄目出し（規律を課さない — CLAUDE.md「W に規律を課さない」）
- スライドの生成（それは `/promote`）
