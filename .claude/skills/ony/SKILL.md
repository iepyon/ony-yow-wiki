# /ony — 朝: 今日やることから逆算して記録し、ドラフト PR まで

共通規約は [CLAUDE.md](../../../CLAUDE.md)、カードの型と診断表の正本は
[ontology.yaml](../../../ontology.yaml)。ここには固有の手順だけを書く。

## 手順

1. **日付とブランチ** — `date +%Y-%m-%dT%H:%M` で日時を取る。
   ブランチ `day/<YYYY-MM-DD>` に居なければ main から切る（既にあれば switch）。
2. **今日やることを聞く** — 冒頭は **「今日やること（Y）は？（複数可）」とだけ**手短に聞く。
   説明・例示・目安を付けない。やること自体は複数件まとめて受けてよいが、
   逆算の聞き出しは**1問1回答** — 一度に1つだけ問い、答えを受けてから次を問う。
   **問いには必ず要素ラベルを付ける**（いまどの箱を埋めているかを常に見せる）:
   「**O（起きていること）**: 何が起きているから、やるのですか？」の形。
   ユーザーが自然に話すのは Y（やること）なので、**各 Y から逆算で聞き出す**（原典 p242 の N←Y）:
   - 「それは**何が起きているから**やるのですか？」→ **O**（判断に影響する観察された事実）
   - 「それが終わったとき、**どうなっていてほしい**ですか？」→ **N**（実現したい状態）
   - 「やったら**何が起きそう**ですか？」→ **O2**（任意。無いと夕方の突き合わせができないと1行だけ伝える）
   - 活動が「提案」なら `## 相手O` `## 相手N` も聞く（原典 §5）
   - title はユーザーの言葉から要約して提案。1問は短く、テンポで回す（p160）
   **グリルミー（問いの質）** — 曖昧な答えは受け流さず、**1回だけ**突き返す:
   - O が感想・解釈なら「それは**観測**ですか、感想ですか。何を見ましたか」
   - N が行動なら「それは行動（Y）です。終わったときの**状態**で言うと？」
   - O2 が願望なら「それは望み（N）ですか、**予測**ですか。実際に起きるのは何ですか」
   - Y が他人任せなら「それは**自分たちが実行可能**ですか（p136）」
   突き返しても曖昧なままなら、そのまま記録する（記録は止めない — p152。判定はレビューの仕事）。
3. **6活動を1語ずつ選ばせる** — `観察 / 仮説立案 / 実行 / 計画 / 提案`（検証は `/yow`）。
   実行は途中経過の記録として受ける。推定して提案してよいが、**決めるのはユーザー**。
4. **カード作成** — `templates/ony.md` から `raw/ony/<ID>.md` を件数分作る
   （ID = `YYYYMMDD-NN`、NN は同日の最大+1・ゼロ詰め2桁）。
5. **lint と診断** — `uv run --with pyyaml --no-project python3 tools/oylint.py`。
   info（引き算診断）が出たら**そのまま1行で伝える**（例: 「〈計画〉で O が空 → 机上の空論。
   このまま記録もできます」）。**記録は止めない**（p152）。error は直してから進む。
6. **デッキ再生成** — `uv run --with pyyaml --no-project python3 tools/gen_deck.py`
   （全カードは週デッキに自動掲載される。cards も wiki の一種）。
7. **カードごとに単独コミット** — YOW と別コミットにすることが予測の事前性の証明
   （push で GitHub のタイムスタンプにも残る）:
   ```bash
   git add raw/ony/<ID>.md && git commit -m "ony: <ID> <title>"
   ```
   最後に `git add wiki/ && git commit -m "wiki: <日付> 朝の再生成"`。
8. **ドラフト PR** — push して、その日の PR が無ければドラフトで作る。
   **本文はスライド画像**（A3 ライト）を生成して渡す — 手書きしない。
   **push が先**（本文の画像 URL は push 済みの SHA で固定される）:
   ```bash
   git push -u origin day/<YYYY-MM-DD>
   uv run --with pyyaml --no-project python3 tools/gen_pr_body.py > /tmp/pr-body.md
   gh pr create --draft --title "<YYYY-MM-DD> の ONY-YOW" --body-file /tmp/pr-body.md
   ```
   既にあればコミットを積み、本文も同じ手順で作り直す（`gh pr edit <番号> --body-file /tmp/pr-body.md`）。
9. **朝レビュー（自動）** — 続けて **[/onyw-review の手順](../onyw-review/SKILL.md) をそのまま実行**し、
   計画段階の3観点コメントを PR に投稿する（ONY のみの朝モード — 観点の力点は
   onyw-review 側の「PR の状態で力点を変える」を参照）。
10. **確認** — PR の URL・今日のループ一覧（ID / title / O2）・レビューコメントの URL を見せて終わる。

## してはいけないこと

- 既存カードの編集（このスキルは新規作成のみ）
- 6活動の自動確定（提案まで。選ぶのは人）
- O/N をこちらで創作する（逆算の**問い**は出すが、答えを埋めるのは人）
- PR を ready にする・マージする（ready 化とレビューは夕方の /yow が行い、マージは本人）
